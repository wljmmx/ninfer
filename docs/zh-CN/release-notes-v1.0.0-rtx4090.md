# 发布说明：RTX 4090（sm_89）v1.0.0-rtx4090

版本：`v1.0.0-rtx4090-643-gba33b85a`（2026-11-08），发布目录 `R:\infer`，模型根 `R:\model`。

本版把 RTX 4090 线从"源码可构建"补成"可直接运行的发布目录"（二进制 + 匹配 PDB + 转换器 +
两套前端 + 文档），并落地运行时控制器、KV tier 前缀索引与运行期池/KV 重分配。**默认路径逐位
不变**（见"兼容性"）。

## 本版内容

1. **运行时控制器（v8 §9–12）。** 参数总线登记 22 个运行期参数，带边界与拒绝原因；三个有实测
   支撑的判据在线生效：
   - **并发**：专家覆盖率低于 80% 且车道数大于 1 时串行化——8 GiB 档、四路 256 token 负载，
     中位 75.7 s 对 87.4 s；19.4 GiB 全驻留档零翻转。
   - **预取**：按 usefulness 判定，读前读实测为零时自动关闭（本机 8 GiB 档两臂吞吐统计等价，
     价值是零成本识别并关掉无用 I/O）。
   - **专家池慢调（L1）**：每 60 s 最多 512 MiB 一格，3% 回退护栏，只在 idle 窗口经
     `resize_expert_pool` 契约执行。实测发现上行受构造期 `slots_max` 封顶：想用 12 GiB 池
     必须以该值启动，运行期只能降。
   `--controller-mode auto|stable|performance` 选择策略；serve 暴露 `/control/state`、
   `/control/mode`、`/control/freeze`。整步图捕获是构造期决策，运行期如实登记为 no-executor
   （分层图实测收益为零，不做挂羊头接线）。
2. **KV tier 前缀索引（Q54）。** tier 目录持久化 frontier sidecar（带校验，坏文件回退为无索引）；
   更长的请求恢复自己前缀里最长的缓存点：397+103 token 命中 397 点（TTFT 327 ms 对冷跑
   3,957 ms），397+3,703 token 同样命中（1,781 ms 对 7,035 ms），输出与冷跑逐 token 一致。
3. **运行期池/KV 重分配通过负载验收。** 修出三个真实缺陷：resize 后已发布 offset 表未失效
   （会读已归还段）、增量发布基线被 resize 破坏、idle 双读被统计相位穿透（长 prefill 期间
   gauge 全零）。修复后：负载中拒绝、空闲时零扰动、往返后 token 与对照一致。
4. **q4 分档按实测收敛（K8）。** 265 点 sweep 全量定罪：12 个 shape span 改用 sm_89 实测最优核
   （这些 span 上 −9%…−38%），其余 span 保持 5090 实测值并逐条给出"测量后无罪"数字。
5. **遗留项闭环。** A1（auto KV 容量的三值日志/断言/降级用例；原"崩溃"4 轮不复现，长请求被
   400 明确拒绝）、A4（ExpertStream 析构不注销进程级注册表 → 悬垂 stream 堆破坏，修复后 10/10
   通过）、K6（block-scaled NVFP4 的宏全历史零定义，改挂构建实际拥有的 opt-in）。
6. **文档与发布物。** README 增加"近期更新"与 4090 双模型基线；新增中文 README 与
   [中文 KV/显存说明](kv-cache-and-eviction.md)；发布目录补带 `README.zh-CN.md`、
   `docs\performance\` 与 `docs\zh-CN\`。

三个必须随数字一起读的性质：

- **池必须先钉死再比较。** 默认自动曲线池会让数百个专家落 CPU：同一二进制在 2k/4k 预填充只测得
  374–632 tok/s，单轮离散度 3.3 倍（pp4096 单轮 3.78 s … 12.35 s）；钉到 19,456 MiB 全驻留后
  离散度 <5%，上表才是硬件真实值。
- **DFlash 的预填充开销约 1%，那 4.6 倍是驻留问题。** 草稿的 context append 在 1,024 token 块上
  实测 1.14 / 0.99 ms（特征投影 0.54、六层 context K/V 投影 0.44、key RMSNorm 0.03、RoPE 0.03、
  草稿 KV append 0.10），目标块 88–93 ms，即 1.2–1.4%。表里 2,225 tok/s 那一行的池是 18,685 MiB
  （DFlash 的 KV 预留 431 MiB 使 19,456 的钉值让位），423/10,240 个专家在 host 层；同一池关掉草稿
  实测 1,731.6 tok/s。解码端仍以 88% 接受率收回（522–547 对无投机 236–249），这是保留它的理由；
  预填充型负载仍应关掉草稿，但原因记作“池容量”，不是“草稿要跑一遍 prompt”。
- **32k MoE 行本轮未测，不估算。** 全驻留池下 rk4v4-e8 的 KV 装得下 32k，但长预填充超出本轮
  预算（19 分钟未完成一轮预热加三次测量），流式配置仍在 CPU 分区线上调优；dense 27B 行是长
  上下文参考。

## 兼容性

- 默认路径逐位不变：门禁 `default PPL 7.441868`、`selector-off dump 636e38de95046781`、
  解码哈希 `d093ac2070ab3292`、Accuracy 全命中、回归 0。
- grouped-MoE 困惑度三点**按纪律重录**为 `7.108737 / 7.766837 / 6.469093`：默认 CPU 专家路径
  改为镜像设备侧舍入口径（token 档平面保 FP32、grouped 档 down 值按路由序合并），位移
  0.11–0.17%。归因是实测的——把该提交三个文件回退到父提交重建，同一点逐位复现旧值
  `7.779849`；不是漂移，是口径变更，故按基线重录而非接受。
- split 档（1% 容差）与 27B byte gates 不受影响。
- `--kv-evict` 默认仍为 `off`；空闲降级默认 60000 ms（上一版引入，逐字比对输出中性）。

## 已知限制

- `nvfp4` KV 与 NVFP4 权重需要 Blackwell（sm_120a）；RTX 4090 上启动即拒绝，请使用
  groupwise-int 工件。
- 运行期 KV 重分配仍有两个 open 项（入口 hand-off 竞态一次实测穿透但无撕裂、降档后 token
  发散未定位），因此 `kv_pages` 在参数总线上保持拒绝；L1 只有专家池半边可接。
- 专家池上行慢调受构造期 `slots_max` 封顶，运行期只能降；需要更大池请以该值启动。
- 整步图捕获为构造期决策，运行期不可翻转（已登记 no-executor）。
- e2 工件（22.8 GB mmap）构造期有低概率不稳（预存族，本轮 6 连跑未再现）；失败时按 `[kv]`
  三值日志与 `[fallback]` 行判断。
- B2（NVFP4 宽批）仅 sm_120a 可验证。

## 历史版本
